# テストの読みかた

このアプリが何を保証しているかは、次の3つを読めば分かる。
細かい単体テストは置いていない。ふるまいと異常系だけを見ている。

| ファイル | 見ていること | 動かしかた |
| --- | --- | --- |
| `test_output.py` | ブラウザがつくった音を測る。長さ・音程・声の高さ・鳴り終わり | `uv run pytest` |
| `test_reject.py` | 音階にできない音をどう弾くか。ノイズ・小さすぎ・短すぎ | `uv run pytest` |
| `test_cli.py` | 測るコマンドのふるまい | `uv run pytest` |
| `e2e/run.mjs` | 画面1から画面2まで、実ブラウザで通す | `npm test` |

## なぜブラウザを回すのか

音をつくるのは `docs/` の JavaScript だけで、Python は同じ処理を持たない。
だからテストもまず `tools/generate.mjs` でブラウザに音をつくらせ、
そのあと Python でその WAV を測る。

**測っている対象が、当日子どもが動かすコードそのもの**になる。
以前は Python 側にも同じアルゴリズムを持たせて突き合わせていたが、
それだと「2つの実装が一致している」ことしか分からなかった。

`conftest.py` がブラウザを一度だけ立ち上げて全ケースぶんをまとめてつくるので、
テスト全体でも2秒ほどで終わる。

音の高さは librosa で測り直している。`docs/sound/pitch.js` とは別のものさしを
当てることで、検出そのものが間違っていないかも同時に確かめられる。

## 要るもの

Google Chrome と node。どちらも無ければテストは自動で飛ばす。
