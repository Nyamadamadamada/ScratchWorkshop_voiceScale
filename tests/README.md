# テストの読みかた

このアプリが何を保証しているかは、次の4つを読めば分かる。
細かい単体テストは置いていない。ふるまいと異常系だけを見ている。

| ファイル | 見ていること |
| --- | --- |
| `test_scale.py` | 声を入れると何ができるか。8音の長さ・音程・声の高さの保たれかた |
| `test_reject.py` | 音階にできない音をどう弾くか。ノイズ・無音・短すぎ・音程が動く |
| `test_cli.py` | コマンドのふるまいと終了コード |
| `test_parity.py` | ブラウザの JavaScript と手元の Python が同じ答えを出すか |
| `e2e/run.mjs` | 実ブラウザで画面1から画面3まで通るか |

`conftest.py` に、テストで使う音をつくる関数がまとまっている。
`声(300)` `滑る声()` `ささやき声(rng)` のように日本語で呼べる。

## なぜ突き合わせテストが要るか

同じ処理を JavaScript と Python の両方に書いてある。ブラウザで動くのは
JavaScript のほうで、Python は見本音源づくりと検証に使う。
ここがずれると、講師が手元でつくった見本と、当日子どもの画面でできあがるものが
食い違ってしまう。

## 実ブラウザのテスト

```sh
uv run python -m http.server -d app 8765   # 別の端末で
npm install && npm test
```

マイクの代わりに、既知の波形を `getUserMedia` へ流し込んでいる。
Chrome の偽マイク機能は指定したファイルを再生してくれなかったため、この方式にした。

実物のマイクを使った録音だけは自動では確かめられない。
当日のパソコンで一度は人が試す必要がある。
